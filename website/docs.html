Getting Started

Documentation

Keeto is a zero-config AI observability library for Python. It intercepts every LLM call your app makes — automatically — and gives you latency, token counts, cost, and dashboards with two lines of code.

Installation

Requires Python 3.11+. The core package has no heavy dependencies.

terminal
# core pip install keeto # with SQLite persistence + interactive TUI pip install "keeto[sqlite,tui]" # everything pip install "keeto[sqlite,tui,web,otel]"
ExtraWhat it adds
keeto[sqlite]Persistent SQLite storage via aiosqlite — traces survive process restarts
keeto[tui]Interactive Textual terminal dashboard
keeto[web]Browser dashboard (FastAPI + HTMX + SSE)
keeto[otel]OpenTelemetry OTLP exporter for Jaeger, Tempo, etc.
keeto[postgres]PostgreSQL storage backend via asyncpg

Quickstart

Two lines instrument your entire application. No wrappers, no base classes, no config files.

1
Start the monitor
Call monitor.start() before any AI calls. Keeto auto-detects installed SDKs.
2
Use your AI SDK normally
No changes to existing code. Every call is captured transparently.
3
View the dashboard
Call monitor.dashboard() to see latency, tokens, cost, and errors.
app.py
from keeto import monitor monitor.start() # keeto: loaded plugins → openai import openai client = openai.OpenAI() response = client.chat.completions.create( model="gpt-4o-mini", messages=[{"role": "user", "content": "What is the capital of France?"}], ) print(response.choices[0].message.content) monitor.dashboard() # → shows latency, tokens, cost
Core API

monitor.start()

Starts the background pipeline and installs all plugins. Safe to call multiple times — subsequent calls are no-ops. Raises nothing; if a plugin fails to load, it is silently skipped.

from keeto import monitor monitor.start() # auto=True by default # or via context manager (auto-stops on exit) with monitor: response = await client.chat.completions.create(...)
💡
Set KEETO_DISABLED=1 in the environment to make monitor.start() a no-op — useful for tests and CI where you don't want tracing overhead.

@trace decorator

Wraps any sync or async function as a named, timed span. Common stage names are auto-mapped to the right SpanKind — no explicit kind needed.

pipeline.py
from keeto import monitor, trace monitor.start() @trace("embedding") # → SpanKind.EMBEDDING def embed(text: str) -> list[float]: ... @trace("retrieval") # → SpanKind.RETRIEVAL async def search(vec: list) -> list[str]: ... @trace("llm") # → SpanKind.LLM def generate(docs: list) -> str: ... # also available as monitor.trace() for custom Monitor instances @monitor.trace("rerank", kind=SpanKind.RETRIEVAL) def rerank(docs): ...

Auto kind mapping

Name patternSpanKind
embedding, embed, embeddingsEMBEDDING
retrieval, retrieve, search, vector-search, rerankRETRIEVAL
llm, generate, completion, inference, chatLLM
tool, tool-callTOOL
chain, pipeline, ragCHAIN
agentAGENT
anything elseCUSTOM

monitor.span()

Context manager for manual span creation. Use it to group multiple @trace-decorated stages under a named root span.

with monitor.span("rag-pipeline") as ctx: ctx.set_attribute("query", query) vecs = embed(query) docs = await search(vecs) answer = generate(docs) # produces: rag-pipeline → embedding → retrieval → llm

monitor.pipeline_breakdown()

Prints a Rich latency table for the most recent trace — or pass trace= to inspect any historical one. Shows each stage in start-time order, a total row, and calls out the slowest stage.

monitor.pipeline_breakdown() # most recent trace traces = list(monitor.traces) monitor.pipeline_breakdown(trace=traces[-2]) # any specific trace
output
Trace a3f8bc12 embedding 18 ms retrieval 12 ms rerank 65 ms llm 1100 ms ────────────────────── Total 1195 ms Slowest stage: llm (92.1%)

monitor.dashboard()

Three dashboard modes, each requiring different extras.

monitor.dashboard() # Rich table — no extra deps monitor.dashboard("tui") # Textual TUI — keeto[tui] monitor.dashboard("web") # browser — keeto[web]
ModeExtraDescription
"rich"nonePrints a summary table with cost, tokens, latency P50/P95 to the terminal
"tui"keeto[tui]Interactive Textual app — trace list, waterfall timeline, cost panel, live refresh
"web"keeto[web]Auto-opens browser; FastAPI + HTMX + SSE for real-time updates

monitor.export()

Export captured traces to multiple formats. Format is inferred from the file extension when a path is given.

monitor.export("traces.json") monitor.export("traces.csv") monitor.export(format="otel", endpoint="http://jaeger:4317") monitor.export(format="langsmith", project_name="my-project") monitor.export(format="mlflow", experiment_name="prod") # filter by time range monitor.export("traces.json", since="2024-01-01", until="2024-01-31")

monitor.recommendations()

Returns a RecommendationsReport with rule-based findings across all captured traces.

report = monitor.recommendations() print(report) # keeto recommendations: # [!] [prompt-size] Prompt exceeds 75% of context window on 3 traces # [i] [cache-candidate] Identical prompt sent 5× — consider caching # [i] [model-switch] gpt-4o tasks could use gpt-4o-mini at 10× lower cost

Rules that fire:

  • prompt-size — prompt exceeds 75% of the model's context window
  • cache-candidate — identical prompt sent more than twice in a session
  • model-switch — task pattern suggests a cheaper model is viable
  • context-waste — large system prompt repeated on every call
  • retry-loop — same prompt retried more than 3 times
  • cost-anomaly — span cost more than 2σ above session mean
Configuration

Monitor options

from keeto import Monitor from keeto.storage.sqlite import SQLiteStorage monitor = Monitor( storage=SQLiteStorage("./keeto.db"), sample_rate=1.0, scrub_pii=True, store_prompts=True, auto=True, )
ParameterDefaultDescription
storageMemoryStorage()Storage backend — MemoryStorage, SQLiteStorage, or PostgresStorage
sample_rate1.0Fraction of requests to capture (0.0–1.0). Errors always captured.
scrub_piiFalseRedact PII patterns before storage
pii_patternsNoneExtra regex patterns to redact (requires scrub_pii=True)
store_promptsTrueSet False to store metadata only (no prompt/response content)
autoTrueAuto-detect and load plugins for installed SDKs

Storage backends

MemoryStorage default

Ring buffer. Zero dependencies. Traces lost on process exit. Default max 1000 traces.

from keeto.storage.memory import MemoryStorage monitor = Monitor(storage=MemoryStorage(max_traces=500))

SQLiteStorage keeto[sqlite]

Persists across restarts. Auto-migrates schema on first connect. WAL mode for performance.

from keeto.storage.sqlite import SQLiteStorage monitor = Monitor(storage=SQLiteStorage("./keeto.db"))

PostgresStorage keeto[postgres]

asyncpg connection pool. Date-partitioned for performance. For team/production deployments.

from keeto.storage.postgres import PostgresStorage monitor = Monitor( storage=PostgresStorage("postgresql://user:pass@localhost/keeto") )

Budget alerts

Set cost or token thresholds. Keeto logs a warning (and fires a webhook if configured) the moment a budget is crossed.

monitor.set_budget( daily_usd=10.0, session_usd=2.0, ) monitor.set_token_budget( daily=500_000, monthly=1_000_000, ) # optional: webhook on budget breach monitor.set_webhook( url="https://hooks.slack.com/...", on_budget=True, on_error=True, )

PII scrubbing

Enable scrub_pii=True to redact sensitive data before it touches storage. Patterns applied to all span attributes including prompt and response content.

PatternReplaced with
Email addresses[EMAIL]
US phone numbers[PHONE]
Social Security Numbers[SSN]
16-digit credit card numbers[CARD]
monitor = Monitor( scrub_pii=True, pii_patterns=[r"\bACCT-\d{8}\b"], # custom → [REDACTED] )

Sampling

For high-traffic services, capture a fraction of requests. Error spans are always captured regardless of the sample rate.

monitor = Monitor(sample_rate=0.1) # capture 10%
Integrations

Auto-detected SDKs

Keeto wraps the httpx transport used by every major AI SDK. Install the SDK, call monitor.start(), and every request is captured.

OpenAI
Chat, embeddings, tool calls, streaming. Token counts and cost computed automatically.
Anthropic
Messages API, tool use, streaming. Cached token tracking supported.
LangChain
Auto-registered as a global callback handler. Captures LLM, chain, and tool spans.
LlamaIndex
Hooks into the LlamaIndex instrumentation dispatcher for LLM and embedding events.
LiteLLM
Appended to litellm.callbacks. Uses LiteLLM's own cost calculation when available.
Google Gemini
Patches generate_content and generate_content_async on GenerativeModel.
Ollama
Patches ollama.chat, ollama.generate, and AsyncClient. Cost is $0 (local inference).
OpenAI Agents SDK
Registers a TracingProcessor to capture agent, LLM, and function-call spans.
PydanticAI
Wraps Agent.run / Agent.run_sync with an AGENT span. Child LLM spans nest underneath.
FastAPI
ASGI middleware that creates a trace per HTTP request so AI calls are grouped by request.
vLLM
Uses OpenAI SDK pointed at vLLM's base_url — captured by the OpenAI plugin automatically.

Custom pipelines

Use @trace to instrument any Python function — sync or async. Nest decorated stages inside monitor.span() to produce a parent-child trace tree visible in the dashboard as a waterfall.

rag.py
from keeto import monitor, trace monitor.start() @trace("embedding") def embed(text): ... @trace("retrieval") async def search(vec): ... @trace("rerank") def rerank(docs, query): ... @trace("llm") def generate(docs): ... async def rag(query: str) -> str: with monitor.span("rag-pipeline") as ctx: ctx.set_attribute("query", query) vecs = embed(query) docs = await search(vecs) docs = rerank(docs, query) return generate(docs)
Exporters

JSON & CSV

No extra dependencies required.

monitor.export("traces.json") monitor.export("traces.csv") monitor.export("week.json", since="2024-06-01", until="2024-06-07")

OpenTelemetry keeto[otel]

Ships traces to any OTLP-compatible collector — Jaeger, Grafana Tempo, OpenTelemetry Collector.

# gRPC (default) monitor.export(format="otel", endpoint="http://jaeger:4317") # HTTP/protobuf monitor.export(format="otel", endpoint="http://collector:4318", protocol="http")

LangSmith

Export to LangSmith, or import LangSmith runs into Keeto for comparison.

# export monitor.export(format="langsmith", project_name="my-project") # import for comparison count = monitor.import_langsmith("my-project", limit=50) monitor.compare(monitor.traces[0], monitor.traces[1])
CLI

keeto CLI

The keeto command reads from a SQLite database (./keeto.db or ~/.keeto/keeto.db by default, or --db PATH).

CommandDescription
keeto tracesList recent traces (table or JSON). Filter by --provider, --model, --errors.
keeto dashboardLaunch TUI or web dashboard.
keeto replay <id>Re-send a captured request to the provider.
keeto exportExport traces to JSON, CSV, or OTLP.
keeto analyzePrint the recommendations report.
keeto compare <id1> <id2>Side-by-side latency and cost diff between two traces.
keeto configGet/set/list config values in ~/.keeto/config.toml.
keeto doctorDiagnose setup — checks installed plugins, storage, Python version.
terminal
# list last 20 traces $ keeto traces --db ./keeto.db # only errors, JSON output $ keeto traces --errors --format json # export to file $ keeto export --format json --output traces.json # launch TUI $ keeto dashboard --mode tui
